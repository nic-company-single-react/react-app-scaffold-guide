# [가이드] 프론트엔드 공통 개발자 — 폐쇄망 SI 초기 세팅

> 대상: 프론트엔드 공통 개발자 (기반 세팅 담당)
> 목적: 업무 개발자 투입 즉시 개발 가능하도록 반입~기반작업을 완성한다.
> 전제: 의존성은 **node_modules 통째 반입** / 배포 방식 **미정(서브경로·루트 양쪽 준비)** / HashRouter 고정.
> 관련: 퍼블리셔 작업은 [초기세팅-퍼블리셔-가이드.md](../publishing-guide/초기세팅-퍼블리셔-가이드.md) 참조. 공통 개발자는 퍼블리셔에게 테마·규칙을 **가이드로 제공**한다.

## Phase 0. 반입 전 사전 준비 (외부망/인터넷 환경)

- [ ] **Node 버전 확정·고정** — `package.json`에 `engines` 없고 `.nvmrc`도 없다. 의존성이 vite8/ts6/@types/node24 계열이라 **Node 20+**가 필수이며, 검증 기준 버전은 Node <Var k="nodeVersion" plain /> / npm <Var k="npmVersion" plain />.
      → `.nvmrc` 추가 또는 반입 문서에 버전 명시 + **Node 설치본 함께 반입**.
- [ ] **`npm ci`로 재현 설치**(package-lock 기준) → `node_modules/` 통째 압축. `npm install`(lock 갱신)이 아닌 `ci` 사용.
- [ ] **디자인 토큰 CSS 최신화 확인(중요)** — `npm run build`는 `tsc -b && vite build`이며 **토큰 빌드를 포함하지 않는다**. 생성물(`src/assets/styles/tokens/*.css`)이 저장소에 커밋되어 있어서 빌드는 통과하지만, 토큰 JSON을 고쳤다면 `npm run build:tokens`(또는 `npm run dev`)를 돌린 뒤 **생성된 CSS까지 커밋**해야 배포본에 반영된다.
- [ ] **빌드 사전 검증** — `npm run build:tokens` → `npm run build` 순으로 성공 확인 후 반입.
- [ ] **Playwright 브라우저 바이너리 결정** — `playwright` + `@vitest/browser-playwright`가 Chromium 별도 다운로드를 요구한다.
      폐쇄망에서 `*.browser.test.tsx`(vitest `browser` project) 미동작 → (a) 브라우저 캐시 반입(Windows: `%USERPROFILE%\AppData\Local\ms-playwright`, Linux/macOS: `~/.cache/ms-playwright`), or (b) 브라우저 테스트 제외하고 `vitest run --project unit`만 운영. **jsdom 단위테스트는 정상.**
- [ ] **외부 의존 문서 스냅샷** — README의 가이드 링크·데모 사이트(<Var k="exampleAppUrl" />)·Storybook(<Var k="storybookUrl" />)은 폐쇄망 접근 불가 → 캡처/PDF 또는 `npm run build-storybook` 정적본 반입.
- [ ] **반입 목록 확정** — 소스(권장 `git bundle`, or zip) + `node_modules.zip` + Node 설치본 + (선택)브라우저 캐시 + 문서 스냅샷.
      폰트는 이미 번들되어 **CDN 의존 없음**(`@fontsource-variable/geist` npm 패키지 + `src/assets/fonts/outfit/` 셀프호스팅).

## Phase 3. 환경/설정 커스터마이징 (핵심 수정 지점)

수정 지점은 **`.env` 계열 + `src/config/*.config.ts` 뿐**(core 불가침). 저장소에 추적되는 env 파일은 `.env`(로컬/개발)·`.env.production`(운영) 2개이며, `.gitignore`가 `*.local`을 제외하므로 사이트별 비밀값은 `.env.local`에 둔다.

- [ ] **3환경(로컬/개발/운영) 값 정의**:

| 변수 | `.env` 현재값 | `.env.production` 현재값 | 조치 |
| --- | --- | --- | --- |
| `PORT` | `5173` | `5173` | dev 서버 포트 |
| `VITE_BASE_URL` | `/` | `/axiom/react/` | 배포 서브경로. **끝 슬래시 필수** (`index.html`의 `%VITE_BASE_URL%logo.ico`) |
| `VITE_ROUTER_BASENAME` | `/` | `/` | HashRouter라 **양쪽 다 `/` 유지**(서브경로 접두어는 `VITE_BASE_URL`이 처리) |
| `VITE_API_BASE_URL` | `https://jsonplaceholder.typicode.com` | `/` | **개발값이 외부 도메인 → 폐쇄망 내부 API 주소/상대경로로 교체(필수)** |
| `VITE_SERVER_URL` | `http://localhost:4000` | (빈 값) | `vite.config.ts` dev proxy `/api` 타겟 = 내부 API 서버 |
| `VITE_LOCALSTORAGE_TOKEN_NAME` | `access_token` | 동일 | `auth.config.ts`가 사용 |
| `VITE_THEME_STORAGE_KEY` | `theme` | 동일 | `index.html` FOUC 스크립트와 `theme.config.ts`가 공유하는 단일 소스 |
| `VITE_SPLASH_BG` / `_BG_DARK` / `_ACCENT` / `_LOGO` | `#ffffff` / `#0b0f19` / `#4f46e5` / `logo.ico` | 동일 | 초기 스플래시(흰 화면 방지). 사이트 브랜드 색으로 교체 |

- [ ] **`src/config/` 조정** — **SI가 만지는 유일한 설정 레이어**(5개 파일 + `index.ts` 배럴).
  - `api.config.ts` — `baseURL`(= `VITE_API_BASE_URL`). `main.tsx`가 `initApiConfig()`로 core에 주입.
  - `auth.config.ts` — `tokenStorageKey`, `loginPath: '/auth/login'`. ⚠️ **해당 로그인 라우트는 아직 없다.** `shared/components/router/ProtectedRoute.tsx`도 존재만 하고 라우터에 미연결 → 인증 도입 시 로그인 도메인 신설 + `ProtectedRoute` 연결이 SI 몫.
  - `query.config.ts` — 현재 비어 있음(core 기본값 사용). 캐시 정책 바꿀 키만 기입.
  - `router.config.ts` — `basename`(= `VITE_ROUTER_BASENAME`). react-router 옵션 추가 지점.
  - `theme.config.ts` — `storageKey`, `defaultTheme: 'light'`, `darkClassName: 'dark'`.
- [ ] **API 연동 전략 확정**(배포 미정 → 양쪽 문서화):
  - 동일 origin: `VITE_API_BASE_URL=/` (상대경로 → `core/api/api-client.ts`가 `window.location.origin` 기준으로 절대화). HashRouter라 **서버 rewrite 불필요**.
  - 별도 backend origin: 절대 URL + CORS/프록시 고려. ⚠️ axios 인스턴스가 **`withCredentials = true` 고정**이라 교차 출처 시 서버에 `Access-Control-Allow-Credentials` + 명시적 Origin 허용이 필요하다.
  - 인증 토큰은 `shared/auth/setup-auth-interceptor.ts`가 매 요청 `Authorization: Bearer` 주입(등록은 `main.tsx`에서 1회). 401 자동 로그아웃/리프레시는 **미구현 자리**만 있음.
- [ ] **브랜드 자산 교체** — `index.html`의 `<title>`(현재 `react-app-scaffold`), `public/logo.ico`·`favicon.svg`·`icons.svg`, 스플래시 색상(`VITE_SPLASH_*`).

## Phase 4. 레이아웃·테마 기반작업 (공통 개발자 몫 + 퍼블리셔 협업)

> 색상/톤앤매너 값 자체는 퍼블리셔가 [초기세팅-퍼블리셔-가이드.md](../publishing-guide/초기세팅-퍼블리셔-가이드.md)에서 작업. 공통 개발자는 **연결·스위치·빌드·구조**를 담당.

- [ ] **테마/레이아웃 스위치 교체(딱 3곳)** — `src/shared/layouts/index.ts`의 `RootLayout` export + `assets/styles/app.css`의 layout import + theme import.
      레이아웃 커스터마이즈 시 `shared/layouts/default/` 폴더 통째 복제(자체완결형 모듈: `components`·`config`·`context`·`hooks`·`providers`) 후 위 3곳만 교체.
- [ ] **디자인 토큰 파이프라인** — `src/design-tokens/primitive/*.json`(color·shadow·spacing·typography) + `semantic/light.json`·`dark.json`이 SSOT → `npm run build:tokens` → `assets/styles/tokens/{primitive,theme-light,theme-dark}.css` 및 `design-tokens/types.d.ts` **자동생성(직접 편집 금지)**.
- [ ] **네비게이션 재구성** — `shared/layouts/default/config/navigation.tsx`(현재 5그룹: Dev Examples / UI Components / API Examples / Utils / Store)를 실제 업무 메뉴로 교체. `othersItems`는 빈 배열.
  - ⚠️ **데드링크 2건 정리** — `/example/use-client-state-1`, `/example/use-client-state-2`는 메뉴에만 있고 라우트가 없다.
  - ⚠️ **하드코딩 URL 제거** — `AppHeader.tsx`의 GitHub 버튼이 스캐폴드 저장소 주소(<Var k="scaffoldRepoUrl" />)를 `window.open(...)`으로 직접 호출한다(`GithubLinkButton` 자체는 `onClick` 주입형이라 재사용 가능).
- [ ] **다크모드 정책 확정** — 자체 `ThemeProvider`(`core/providers/theme`) + `.dark` 클래스 + `VITE_THEME_STORAGE_KEY`. `index.html` 인라인 스크립트가 React 마운트 전에 같은 키를 읽어 FOUC를 막으므로 **키를 바꾸면 양쪽이 자동 동기화**된다. 퍼블리셔에게 CSS Module 규칙(`:global(.dark) .클래스`)과 `@custom-variant dark (&:is(.dark *))` 전달.
- [ ] **퍼블리셔에게 가이드 전달** — [초기세팅-퍼블리셔-가이드.md](../publishing-guide/초기세팅-퍼블리셔-가이드.md) + 예제 카탈로그(UI 컴포넌트 예제 34페이지) + 토큰 참조표(Storybook `DesignTokens.stories`) 안내.

## Phase 5. 프로젝트 구조·컨벤션 확정 (업무 개발자 투입 대비)

- [ ] **example / publishing 정리 정책(중요 — 동작이 다름)** — `src/shared/router/index.tsx` 확인 결과:
  - `publishing/example` → `import.meta.env.DEV`에서만 등록(동적 import라 **운영 번들에서 완전 제외**).
  - `example` → **DEV·운영 양쪽 분기 모두에 등록되어 운영 빌드에도 포함된다.** 학습 레퍼런스로 남길지, 운영 분기에서 제거할지 **명시적으로 결정**할 것(번들 크기·외부 노출 영향 있음). 각 페이지는 `loadable`로 지연 로드되지만 라우트·청크는 생성된다.
  - 참고: `/example/use-api` 예제는 `.env`의 `VITE_API_BASE_URL`(기본 jsonplaceholder)로 `/posts`를 호출한다 → 운영에 남길 경우 내부 API 주소로 바뀌면서 404가 날 수 있다.
- [ ] **업무 도메인 뼈대 규칙** — `domains/<업무>/` 하위 `pages/`·`components/`(pages 미러링)·`store/`·`router/`. CLAUDE.md 폴더 규칙 준수(페이지 안에 보조 컴포넌트 인라인 정의 금지, props는 `export interface I<Component>Props`).
- [ ] **라우터 등록 3스텝 문서화** — 페이지 생성 → `domains/<d>/router/index.tsx`에 `loadable(() => import(...))` + `{ path, element, name }` 추가 → `shared/router/index.tsx`에 도메인 라우터 연결 + `navigation.tsx` 메뉴 추가.
- [ ] **상태관리 배치 규칙** — `defineStore`/`createStore`(`@axiom/store`)만 사용. 도메인전용 `domains/<d>/store/`, 공유 승격 `shared/store/`, core 전역 `core/ui/store.ts`.
- [ ] **공통 인프라 사용법 온보딩** — `main.tsx`에서 등록되는 전역 `$util`/`$ui`/`$router`, `@axiom/components/ui` 배럴(shadcn 36종 + `SmartTable`·`CodeBlock`은 배럴 내부에서 동적 분리), `SmartTable`(서버사이드 정렬·페이징·CSV/XLSX), react-query(`useApi`), `api-client`.
- [ ] **경로 alias 공유** — `@/*`, `@axiom/components/ui`, `@axiom/hooks`, `@axiom/store` (vite + tsconfig 양쪽 정의). ⚠️ `@app-types`는 `vite.config.ts`에만 있고 `tsconfig` `paths`에 없어 현재 사용처가 없다 → 쓰려면 tsconfig에 추가.
- [ ] **코드 컨벤션 고정** — ESLint(flat config) + Prettier(**탭, printWidth 120, singleQuote**) + `.vscode/settings.json`(formatOnSave, eslint fixAll, `@axiom` 배럴 우선 자동 import 제한). 커밋/브랜치 전략 합의.

## 체크포인트 요약 (반드시 결정하고 넘어갈 것)

1. Node 버전 고정(`engines`/`.nvmrc` 부재) + Playwright 브라우저 바이너리 반입 여부 (Phase 0)
2. `build`에 토큰 빌드가 없다는 점 — 토큰 수정 시 `build:tokens` 실행 + 생성 CSS 커밋 (Phase 0/6)
3. 라이선스 목록·보안 심사 (Phase 1)
4. 반입 후 무결성 검증 + 내부 git 이전 + 신규 개발자 node_modules 전달 방안 (Phase 2)
5. `.env` 3종 값 확정 — 특히 `VITE_API_BASE_URL`의 외부 도메인 제거 (Phase 3)
6. 인증 로그인 라우트(`/auth/login`) 미구현 + `ProtectedRoute` 미연결 → 인증 도입 범위 결정 (Phase 3)
7. **example 라우터가 운영 빌드에도 포함**된다는 점 — 유지/제거 결정 (Phase 5)
8. 배포 정적서빙 검증(서브경로·루트 양쪽) + Docker/nginx/CI 부재 대응 (Phase 6)
