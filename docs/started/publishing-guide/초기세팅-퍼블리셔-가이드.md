# [가이드] 퍼블리셔 — 폐쇄망 SI 스타일/퍼블리싱

> 대상: 퍼블리셔 (마크업·스타일·디자인 토큰 반영 담당)
> 목적: 공통 개발자가 세팅한 기반 위에서 브랜드 톤앤매너·레이아웃 스타일을 반영하고, 개발자에게 핸드오프한다.
> 관련: 반입·설정·빌드 등 인프라는 공통 개발자 몫 → [초기세팅-프론트공통개발자-가이드.md](../frontend-common/초기세팅-프론트공통개발자-가이드.md) 참조.
> 전제: 스타일 시스템은 **Tailwind v4 + Style Dictionary 토큰 + shadcn 시맨틱 vars + CSS Module(co-location)** 조합. `tailwind.config.js` 없음(v4 방식).

## 스캐폴드 현황 (본 문서의 사실 기준)

| 항목 | 현재 값 |
| --- | --- |
| 스타일 진입점 | `src/assets/styles/app.css` (선언 없이 `@import`만, 5블록) |
| 테마 파일 | `themes/theme-default.css`(niccompany Sky Blue `#499ed8`) · `themes/theme-example-project.css`(주석만 있는 최소 override 템플릿) |
| 토큰 SSOT | `src/design-tokens/primitive/{color,shadow,spacing,typography}.json` + `semantic/{light,dark}.json` |
| 토큰 생성물 | `assets/styles/tokens/{primitive,theme-light,theme-dark}.css` — **직접 편집 금지** |
| 공통 UI | 배럴 `@axiom/components/ui` — shadcn **35종 export** + `SmartTable`·`CodeBlock` (`alert-dialog.tsx`는 파일만 있고 미export) |
| 예제 카탈로그 | `/example/ui-components/*` **34페이지** (사이드바 `UI Components` 그룹) |
| 재스타일 실전 예제 | 34페이지 중 **24페이지**에 CSS Module 예제 동봉 (`*.module.css` 총 34개) |

| 폰트 | 셀프호스팅. body=`font-outfit`(Outfit) / html=`font-sans`(Geist Variable). **CDN 미사용** |

## 0. 시작 전 이해할 3가지

1. **작업 공간은 `src/publishing/`** — Figma → React 1차 작업 공간. 완료 후 개발자가 `domains/`·`shared/`로 이동(핸드오프).
   - ⚠️ **라우터에 등록되어 있다** — `src/shared/router/index.tsx`가 `import.meta.env.DEV`일 때만 `/publishing/example`을 붙인다(동적 import라 **운영 번들에서 완전 제외**). 확인 주소: `http://localhost:5173/#/publishing/example/example-page`.
   - 단, **사이드바 메뉴에는 없다**(`navigation.tsx` 미등록) → 주소를 직접 입력해서 본다.
   - 새 퍼블리싱 페이지를 브라우저로 보려면 `src/publishing/<name>/router/index.tsx` 작성 + `shared/router/index.tsx`의 DEV 분기에 추가(개발자와 협업).
   - 참고: `src/publishing/README.md`에는 아직 "React Router 등록 없음"으로 적혀 있다 → **실제 코드 기준(위)이 맞다**.
2. **스타일 우선순위는 `app.css`의 import 순서** — 아래일수록 우선. 퍼블리셔 수정 구간은 하단 theme/layout 두 곳으로 격리돼 있음.
   `@custom-variant dark (&:is(.dark *))`는 반드시 `app.css` **루트에 직접** 선언되어야 한다(import된 파일 안에 넣으면 `dark:` 유틸이 생성되지 않음).
3. **토큰은 JSON이 원본(SSOT)** — 색상/간격/타이포는 `design-tokens/*.json`을 고치고 `npm run build:tokens`로 생성. 생성된 `assets/styles/tokens/*.css`는 **직접 편집 금지**.
   `npm run dev`가 `build:tokens`를 먼저 실행하므로, **개발 서버를 다시 띄우면 JSON 수정분이 자동 반영**된다. (단 `npm run build`에는 포함 안 됨 → 커밋 전 생성 CSS 확인)

## 1. 퍼블리싱 기본 규칙 (`publishing/README.md` 준수)

- [ ] **Tailwind 유틸리티 + `cn()`만 사용** — publishing 단계에서 **CSS 파일 생성 금지**. (`cn`은 `@/shared/utils/cn`)
- [ ] **공통 UI는 배럴에서 import** — `import { Button, Card, Dialog } from '@axiom/components/ui';` (shadcn 35종 + `SmartTable`·`CodeBlock`). 개별 파일 경로 직접 import 금지.
- [ ] **토큰 클래스로 색상·그림자·타이포 참조** — 하드코딩 금지.
  - 색상: `bg-brand-500`, `text-foreground`, `border-border`, `bg-card`
  - 그림자: `shadow-theme-xs|sm|md|lg|xl`, `shadow-focus-ring`
  - 타이포: `text-theme-xs|sm|xl`, `text-title-sm|md|lg|xl|2xl`
- [ ] **경로 alias `@/` 사용** — 상대경로 남발 금지. (`@/*` → `src/*`)
- [ ] **다크모드는 `dark:` 유틸** — 예 `bg-white dark:bg-neutral-900`. (프로젝트는 `.dark` 클래스 기반)
- [ ] 핸드오프 시 컴포넌트를 `domains/<업무>/` 또는 `shared/`로 이동(개발자 협업).

## 2. 브랜드 색상 테마 작업 (공통 개발자와 협업)

> 스위치 연결(app.css import, layouts/index.ts)은 공통 개발자가 담당. 퍼블리셔는 **색상 값**을 만든다.

- [ ] **프로젝트 테마 파일 생성** — `theme-<project>.css`를 새로 만든다.
  - `theme-example-project.css`는 **전부 주석 처리된 최소 override 템플릿**(`:root`/`.dark`만 있음) → 사용법 확인용.
  - **실제 작업은 `theme-default.css`를 복사해서 시작**하는 편이 빠르다(3블록 전체 구조 + 주석이 들어 있음).
  - 현재 `theme-default.css`는 niccompany(Sky Blue `#499ed8`) 예시 → **신규 SI는 교체 대상**.
- [ ] 테마 파일 3블록 이해하고 채우기:
  1. `@theme inline` — shadcn CSS vars(`--sidebar`/`--card`/`--primary` …)를 Tailwind 유틸로 브리지. **`--font-sans` 지정 위치도 여기**(현재 `'Geist Variable'`), `--radius-*` 스케일도 여기서 `--radius` 기준으로 파생.
  2. `@theme` — `brand-25 ~ brand-950` 스케일을 시그니처 색으로 리매핑. **`--shadow-focus-ring`도 같이 시그니처 색으로 맞출 것**(안 하면 포커스 링만 기본 파랑 `#465fff`으로 남는다).
  3. `:root`(라이트) / `.dark`(다크) — background/foreground/card/primary/border/sidebar/chart 시맨틱 값.
- [ ] **`brand-*` 리매핑을 빠뜨리지 말 것** — 사이드바 active(`menu-item-active`)·검색창 ring 등 레이아웃 유틸이 `brand-*`를 직접 쓰므로, `--primary`만 바꾸면 **메뉴 강조색이 기본 파랑으로 남는다**.
- [ ] **간격/타이포/그림자 등 토큰 조정 시** — `design-tokens/primitive/*.json` + `semantic/light.json`·`dark.json` 수정 → `npm run build:tokens`(또는 `npm run dev` 재기동)로 반영. 생성 CSS는 커밋 대상.
- [ ] **본문 폰트 교체 시** — ① `base/fonts.css`에 `@font-face` 추가(폰트 실물은 `src/assets/fonts/`, **CDN 금지**) → ② `design-tokens/primitive/typography.json`의 `--font-outfit` 계열 값 교체 → ③ `base/typography.css`의 `body { @apply font-outfit }` 확인.

## 3. 레이아웃/컴포넌트 스타일 반영

- [ ] **예제 카탈로그를 레퍼런스로 사용** — DEV 사이드바 `UI Components` 그룹의 **34개 예제 페이지**(`domains/example/pages/ui-components/*Component.tsx`).
      각 페이지 구성: `0. import & 기본 구조` → variant/상태별 예제(`ExCard`) → **CSS Module 재스타일 예제**(`SourceTabs`로 `.tsx`/`.module.css` 원본 동시 표시) → `Props 요약` 테이블. 우측 `SectionNav`로 섹션 바로가기.
- [ ] **shadcn 컴포넌트 재스타일 방법 ① `data-slot` 오버라이드** — 컴포넌트 내부 요소가 `data-slot` 속성을 노출한다.
      실전 예시: `domains/example/components/ui-components/accordion/TransactionDetailAccordion.module.css`
      (`[data-slot="accordion-trigger"]` 등 + 금융권 톤 + 다크모드 `:global(.dark)`). 상세 주석 포함.
      **명시도 팁** — 래퍼 클래스(`.wrap`) 아래에서 슬롯을 2~3단계로 감싸 Tailwind 유틸리티보다 우선순위를 높인다.
- [ ] **재스타일 방법 ② 공개 CSS 변수(테마 계약)** — 컴포넌트 내부 구조를 몰라도 래퍼에서 변수만 세팅하면 동작이 바뀐다.
      현재 `Accordion`이 제공: `--accordion-icon-rotate`(기본 `180deg`) · `--accordion-icon-duration`(`200ms`) · `--accordion-icon-size`(`1rem`) · `--accordion-content-duration`(`0.2s`).
      ※ 이 계약을 노출하는 컴포넌트는 **현재 Accordion 뿐** → 다른 컴포넌트는 `data-slot` 방식으로 처리한다.
- [ ] **재스타일 예제가 이미 있는 컴포넌트(24종)** — 새로 만들지 말고 복사해서 시작할 것.
      accordion · alert · avatar · breadcrumb · card · dialog · drawer · dropdown-menu · input · input-group · native-select · pagination · progress · radiogroup · select · skeleton · slider · spinner · switch · tabs · textarea · toast · toggle · tooltip
      (위치: `domains/example/components/ui-components/<컴포넌트>/*.module.css`)
- [ ] **CSS Module이 필요한 경우(핸드오프 이후)** — co-location 규칙(CLAUDE.md):
  - 파일명 = 소비 주체 이름, 위치 = 소비 주체 바로 옆.
  - 재사용 UI 조각 → `<Component>.module.css`(컴포넌트 옆) / 페이지 전용 → `<Page>.module.css`(페이지 옆) / 도메인 공용 → `domains/<d>/common/styles/`.
  - 다크모드는 `:global(.dark) .클래스`.
- [ ] **레이아웃 조정** — 헤더/사이드바 스타일은 `shared/layouts/default/components/`
      (`AppHeader` · `AppSidebar` · `Backdrop` · `GithubLinkButton` · `ThemeToggleButton` 5개). 메뉴 항목 자체는 `layouts/default/config/navigation.tsx`.
      메뉴 강조 유틸(`menu-item-*`, `menu-dropdown-*`)은 `assets/styles/layout/default/layout.css`에 `@utility`로 정의되어 있다. 구조 변경은 공통 개발자와 협의.

## 4. 확인 & 핸드오프

- [ ] **Storybook으로 토큰/컴포넌트 확인** — `npm run storybook`(포트 6006). `Getting Started/Design Tokens`(토큰 클래스 참조표) · `introduction.mdx`. 인터넷 없이 현장에서 그대로 실행된다.
- [ ] **라이트/다크 양쪽 검수** — 헤더의 `ThemeToggleButton`으로 두 모드 모두 확인. 토큰만 쓰면 대부분 자동으로 따라오지만, **CSS Module에 직접 적은 색은 `:global(.dark)` 블록을 반드시 같이 작성**해야 한다.
- [ ] **앵커 이동 주의** — HashRouter라 `<a href="#id">` 금지(라우트 해시 깨짐). `document.getElementById(id)?.scrollIntoView(...)` 사용.
- [ ] **핸드오프** — `publishing/` 산출물을 개발자와 함께 `domains/`·`shared/`로 이동하고, publishing 단계에서 미룬 CSS Module화(필요분)를 이때 적용. 이동 후 **DEV 분기에 남은 `/publishing/*` 라우트 정리**까지 확인.
